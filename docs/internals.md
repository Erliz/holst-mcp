# Внутренности holst-mcp

Глубокая техническая документация для сопровождающих код: механика чтения/записи, особенности версий Holst, правила подсчёта, детали цветов. Пользовательская документация — [README](../README.md).

## Чтение доски

1. Подключаемся к `127.0.0.1:9222`, находим вкладку с `app.holst.so/board/{id}`. Если такой нет — берём любую вкладку Holst и навигируем её на нужную доску.
2. Через CDP `Runtime.evaluate` выполняем в контексте страницы:
   ```js
   window.ds.yPersistence.yDoc.toJSON()
   ```
3. Получаем JSON со всем содержимым:
   - `documents`: `{ docId: "текст" }` — текстовое содержимое
   - `objects`: `{ oid: { type, position, documentId, ... } }` — визуальные объекты
   - `task-card-statusesStore`, `kanban-*Store`, `reactionsStore` — другие подсистемы

С v0.8 перед отдачей клиента вырезается «мёртвый груз»: аудит удалений (`delete-events-metaStore` с полными снапшотами удалённых объектов) и осиротевшие `documents` без живых ссылок. На тестовой доске это ~70% сырого дампа. Опциональный флаг `includeDeleteEvents: true` тулзы `holst_get_board_content` возвращает неотрезанный вид.

Экономия токенов в `holst_get_board_content`:

- `bbox: {x1,y1,x2,y2}` — только объекты, пересекающие область. Коробка стрелки вычисляется из концов: привязанные концы резолвятся в опорную точку на referenced-объекте, свободные берутся как есть; кривые аппроксимируются коробкой концов.
- `positionsOnly: true` — компактные `{type,x,y,w,h}` без текстов документов; стрелки получают ту же вычисленную коробку вместо бессмысленных нулей.

## Запись на доску

Holst использует **Yjs CRDT** (`window.Yjs` экспортирован глобально). Модель данных:

- `yDoc.getMap('objects')` — Y.Map, ключ = UUID объекта, значение = Y.Map с полями (type, position, documentId, width, height, ...).
- `yDoc.getMap('documents')` — Y.Map, ключ = documentId, значение = Y.Text.

Чтобы добавить стикер:

```js
const yObjects = yDoc.getMap('objects');
const yDocs = yDoc.getMap('documents');

const stickerMap = new Yjs.Map();
stickerMap.set('type', 'sticker');
stickerMap.set('documentId', newDocId);
stickerMap.set('position', { x, y });
// ... другие поля

const yText = new Yjs.Text();
yText.insert(0, 'текст стикера');

yDoc.transact(() => {
  yDocs.set(newDocId, yText);
  yObjects.set(newId, stickerMap);
});
```

Yjs автоматически синкает изменения через WebSocket-провайдер на сервер Holst, доставляет их другим клиентам и решает конфликты при concurrent-редактировании.

На практике запись сложнее — см. [двухслойная модель](#двухслойная-модель-текста-holst--2026-10): часть операций идёт через собственные сервисы приложения (`objectsService.update`, `objectsService.remove`), а не сырые Yjs-структуры.

## Авторизация

Holst использует Bearer-токен в `Authorization` header (НЕ в куках). Токен лежит в `localStorage['social-auth-store'].token`. MCP не знает токен сам — он выполняется в контексте страницы, где локальное хранилище уже доступно. Токен ротируется при логауте: после разлогина тулзы вернут 401, нужно перелогиниться.

## Двухслойная модель текста (Holst ≥ 2026-10)

Рендер текста идёт из Slate-редактора, а не из сырого Y.Text: прямые `Y.Text.insert` лежат в yDoc, но НЕ отображаются, а при монтировании нового объекта приложение затирает документ своей пустой view-model. Поэтому MCP пишет текст через нативный конвейер приложения:

- `update_text`: `ds.store.objects.get(id).editor` → select-all → deleteFragment → paste (для run-цветов — `singleDocumentStore.createFromJSON`), с фолбэком `singleDocumentStore.createFromString`, паузой ~2с на оседание биндинга и ретраями. Верификация срабатывания — параграф/mark-aware (`text-match.js`).
- Запись текста после `add_*` делается с той же паузой; если объект не смонтировался в доменный стор — тулз сам перезагружает вкладку (это лечит и «осиротевшие» редакторы).

Чтение (`get_board_content` и производные) идёт через `toDelta()`.

## Двухслойные удаления

Raw `yObjects.delete()` убирает объект из yDoc, но доменный стор (и канвас) продолжают его рисовать до перезагрузки страницы. Поэтому `delete_object` использует нативный `objectsService.remove(id)` — он удаляет из yDoc И размонтирует объект из стора сразу; при лаге размонтирования тулз самолечится перезагрузкой. Повторное удаление уже удалённого даёт понятную ошибку «object not found».

## Подсчёт живых объектов

Дамп — это весь yDoc, а не только живые объекты. Живые объекты — исключительно ключи плоской карты `content.objects`; остальное — история и метаданные:

- `delete-events-metaStore` — журнал удалений; каждая запись несёт полные снапшоты удалённых объектов `s[]` с обычными полями `type` — наивный скан дампа по `type` считает их живыми.
- `documents` — содержит осиротевшие доки удалённых объектов.
- Вспомогательные kanban-/reactions-/task-card- stores.

Под-счёты `holst_get_board_summary` («стикеров»/«секций»/«текстовых меток») вдобавок фильтруют по непустому тексту и не сходятся с «Объектов» намеренно. Полные правила — `holst_reference` → `countingRules`.

## Цвета: нормализация, гармонизация, roundtrip

- **Только `#RRGGBB`** во всех цветовых параметрах; чтение возвращает hex: int'ы нормализуются (`dump-colors.js`), имена палитры из UI транслируются таблицей `src/palette-data.js` (источник — `docs/palette.md`).
- **Рендер-гармонизация**: насыщенные оттенки Holst рисует приглушённее (тон сохраняется, светлота тянется к ~57–62%) — одинаково для любых входов, детерминированно; бледные/тёмные/серые — дословно. Токен и его hex рендерятся идентично (проверено попиксельно).
- **Нюанс roundtrip**: если агент прочитал переведённый hex UI-объекта и записал обратно — в хранилище станет int, пикер покажет custom вместо свотча (рендер тот же).

## Пунктир стрелок

Собственного `stroke-dasharray` у приложения нет — рендерер вычисляет паттерн из пары (strokeStyle, strokeWidth):

- dashed = `[max(10, 2w), max(10, 2w) + w]`
- dotted = точки `[0.5w, 2w]` round-cap

Любые другие значения молча рисуются сплошной линией. Двух разных пунктирных ритмов не выразить — только выбор dashed/dotted или масштаб `strokeWidth`. Запрос passthrough `strokeDasharray` закрыт как несовместимый с текущим рендерером.

## Подводные камни

- **Holst-апдейт может сломать схему.** Проверено на сборках Holst 0.0.2 (Electron 29.4.6) и 2026-10 (двухслойная текстовая модель). Если в новой версии изменятся имена share-ключей (`documents`, `objects`), кейсы Yjs или window-глобалы (`window.ds`, `window.Yjs`) — нужно править `src/holst.js`.
- **Bearer-токен ротируется при логауте.** Если пользователь разлогинился — MCP отдаст ошибку, нужно запустить `start-holst.sh` и снова залогиниться.
- **CDP-порт нужно держать открытым.** Если Holst упал или перезапущен без флага — MCP не подключится. `start-holst.sh` это лечит.
- **Ничего не блокирует concurrent-редактирование** — если MCP пишет на доску, которую одновременно редактирует человек в UI, Yjs всё мерджит. Но если объект только что удалён человеком, а MCP пытается его обновить — будет ошибка `object not found`.

## Безопасность: что сделано в коде

- Строгая валидация входов: `boardId` — только UUID (защита от навигации вкладки на произвольный URL), координаты/размеры — конечные числа (защита Yjs от `NaN`/`Infinity`), цвета — только `#RRGGBB`, типы — enum-whitelist'ы (единый источник: списки экспортируются из `validate.js`, описания схем и справочник генерируются из них же).
- Проверка origin по `new URL().hostname === 'app.holst.so'` вместо substring (раньше матчился `https://evil.com/?app.holst.so`).
- Таймауты на все CDP-операции + reject зависших запросов при обрыве соединения.
- Санитизация ошибок: стектреки и внутренности не попадают в LLM-контекст.
- `start-holst.sh`: отказ работать, если порт занят не-Holst процессом (анти-спуфинг), `pkill -x` вместо убийства по подстроке, лог в `~/Library/Logs/holst-mcp/` вместо world-readable `/tmp`.
- Зависимости без известных уязвимостей (`npm audit` чист).

## Детали тулзов

### `holst_get_board_content`

```json
{ "boardId": "123e4567-e89b-42d3-a456-426614174000" }
```

Возвращает:

```json
{
  "meta": { "id": "...", "name": "Настя", "workspace_id": "...", ... },
  "content": {
    "documents": { "bb3c0ac3-...": "ЦЕННОСТИ", ... },
    "objects": { "04a54183-...": { "type": "shape", "position": {...}, ... } },
    ...
  }
}
```

### `holst_add_sticker`

```json
{
  "boardId": "...",
  "text": "новый стикер",
  "x": 100,
  "y": 200,
  "width": 192,
  "height": 192
}
```

Возвращает `{ ok: true, id, documentId }` — id нового стикера и его документа.

### `holst_update_text`

```json
{ "boardId": "...", "objectId": "...", "text": "новый текст" }
```

Меняет текст в существующем объекте (стикер/shape/simple-text/подпись стрелки; для стрелок — перезапись `texts[0]` с сохранением позиции метки). `text` можно заменить на `runs: [{text, color, bold}]` — несколько стилей в одном объекте. Не пересоздаёт объект.
